---
name: useavibe-release
description: Cut the release of UseAVibe cycle Z<k> once all PL06=1 problems are implemented (minor x.y.0), or the patch release after an acceptance round with findings (x.y.r) — pre-checks against the local container first, then version, SBOM and changelog per /uat-release §1; tag and push only on the operator's go-ahead.
disable-model-invocation: true
argument-hint: <cycle number k>
---
Prepare the release of cycle Z$ARGUMENTS. No release may be spent on known defects; no participant session of a
running cycle may receive it.

1. `useavibe release-check --app . --cycle $ARGUMENTS` — refuses while a PL06 = 1 problem of the frozen list is
   neither implemented (commit with `Usability-Problem:` trailer) nor deferred and reverted, or while a finding of the
   last round has no fix commit (`Round-Finding:` trailer). It prints the version to cut (minor for round 1, patch later).
2. Pre-checks on the integration commit, in this order; stop at the first failure and report it:
   a. the full gate once more: `npm run test:ci`, `npm run build`, `npm run lint`, `npm run knip`;
   b. `/uat-verify` §1 (clean tree → build + `bash scripts/container-smoke.sh`, 18/18 → run the container);
   c. Playwright suite of all cycles and the automated acceptance-test suite against that container
      (`npm run test:acceptance`; it builds and runs the container itself);
   d. `npm run requirements` (full registry unit layer) — FAIL 0;
   e. `/uat-verify` §3 browser pass for every scenario tagged `@visual` and for the intent of each implemented problem.
3. Then `/uat-release` §1 (version bump, SBOM, roadmap; the changelog section is generated by
   `useavibe changelog --app . --cycle $ARGUMENTS`). Stage it and write the message to
   `.planning/useavibe/COMMIT_MSG`; do not run `git commit` (the pseudonym guard cannot run in the sandbox, O-25) —
   the operator commits outside the sandbox with `git commit -F .planning/useavibe/COMMIT_MSG`.
4. Stop and ask the operator for the go-ahead before `/uat-release` §2 (tag → CI → GHCR). After CI, record the
   published digest with `useavibe release-record --app . --cycle $ARGUMENTS --version <v> --digest <sha256>`.
   Skip `/uat-release` §3–§4 (no developer response to participants).
