## v1.20.1 — Hotfix: production CSP vs. browser (NF, 2026-10-02)
NF report (deployment behind GB-IT nginx + TLS at emd.ukaachen.de): Verläufe shows Plotly's "WebGL is not supported" although the browser supports WebGL.
- **Root cause:** helmet CSP `script-src 'self'` (no `'unsafe-eval'`) — Plotly's regl compiles its WebGL draw calls with `new Function`; the blocked EvalError is reported by Plotly as "WebGL is not supported". Only visible with Individuelle Kurven / Streupunkte (scattergl); Vite dev sends no CSP, so dev/tests never saw it. Reproduced on the published 1.20 image (`new Function` → EvalError, `getContext('webgl')` OK).
- **Fix:** `plotly.js-dist-min` → `plotly.js-strict-dist-min` 3.6.0 (same Plotly, regl code precompiled). CSP unchanged (no `'unsafe-eval'`).
- **Found while reproducing — same class (production CSP, never active in dev):**
  - Phase-17 FOUC inline script in `index.html` blocked → dark-mode users got a light flash on every load. Moved to `public/theme-init.js` (also: no stored theme now counts as 'system', matching ThemeContext).
  - helmet's default `upgrade-insecure-requests` rewrote every asset to `https://` on a plain-HTTP non-localhost host → blank page for the documented `http://<host>:3000` deployment (NF unaffected: TLS). Disabled (`upgradeInsecureRequests: null`); no-op on HTTPS, HSTS still pins TLS.
- **Canaries** in `scripts/container-smoke.sh` (17 checks): no inline `<script>` in index.html, Plotly chunk is the strict build, CSP without `upgrade-insecure-requests`. Negative control: the 1.20 image fails exactly the new canaries.
- **Verified:** test:ci 1325/1325, build, lint, knip; smoke 17/17; in-browser on the rebuilt image: curves + scatter → 9 WebGL canvases, 0 "WebGL not supported", hover tooltip OK; plain-HTTP non-localhost host: asset URLs no longer upgraded.
- **Fonts:** `src/index.css` `@import`ed Google Fonts — blocked by the CSP in production (system-font fallback), and in dev it sent every visitor's IP to Google (GDPR). Now self-hosted: `@fontsource-variable/inter` + `@fontsource-variable/jetbrains-mono` (OFL-1.1) imported in `src/main.tsx`; 12 woff2 subsets in `dist/assets`, the browser fetches only the subsets in use (latin on the login page). Verified in the container: `Inter Variable` loaded from `/assets/`, zero third-party requests, no CSP errors after reload.
